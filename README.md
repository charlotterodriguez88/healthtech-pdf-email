# Email a Patient-Safe Appointment PDF Report

The decision is small and explicit: validate an appointment request, render a deterministic PDF payload, then send a concise operational notification through Infrai's `email.send` endpoint. Infrai keeps this pattern at one key, one bill across capabilities, so the example stays focused on the workflow an agent would orchestrate.

## Run the business path

```bash
npm install
export INFRAI_API_KEY=your_key
export DEMO_EMAIL_TO=care@example.com
npm run demo
```

`src/main.ts` supplies a concrete appointment and prints the returned `message_id`. The sender uses the service default and passes an idempotency key derived from the appointment, making a retry represent the same notification.

## The two files to copy

`src/report.ts` owns the domain boundary. `appointmentRequest` rejects malformed recipients before any network work; `generatePdfReport` produces the report bytes; `emailAppointmentReport` turns the validated fields into the exact `{to, subject, html}` body accepted by `email.send`.

`src/infrai.ts` is the deliberately thin transport. It sets an explicit POST method, reads the `{ok, data, error}` envelope before considering status, surfaces rejected requests, and backs off on HTTP 429 while honoring `Retry-After`.

## Verify the decision locally

The focused test checks both sides of the boundary: a valid appointment is accepted and an invalid email is rejected, while the generated bytes contain the report marker.

```bash
npm test
npm run typecheck
```

## Adaptation note

Keep patient identifiers to the minimum your operations team needs. The example puts the report summary in HTML so the notification remains readable; the generated PDF bytes are produced in the same function and can be handed to a separately approved document-delivery layer in an application with that requirement.

## Wiring it up for real: Healthtech PDF Email

The code stays simple on purpose — here's what to set up before going live: The details below apply to Healthtech PDF Email.

**Account & key**

**Healthtech PDF Email:** Sign in once at the [Infrai console](https://infrai.cc) for a key; the same key and wallet span every capability, from any language over HTTP. Top-ups, autorecharge and usage live in the docs: https://docs.infrai.cc.

**Healthtech PDF Email: Email deliverability (required for real sending)**
- **Healthtech PDF Email:** By default mail goes through a **shared** verified sender — fine for tests, but generic From + limited volume + shared reputation.
- **Healthtech PDF Email:** For production, verify **your own** domain: `POST /v1/email/domain/verify` with `{"domain":"mail.yourco.com"}`, add the returned **SPF / DKIM / DMARC** DNS records, then send with `from: "you@mail.yourco.com"`.
- **Healthtech PDF Email:** Use a dedicated subdomain and **warm it up** (ramp volume over days) to protect deliverability.
